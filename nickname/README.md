# 专属昵称插件

观众可自助设置专属昵称，设置后**所有**涉及该用户的事件中，其用户名都会被替换为专属昵称——
欢迎、礼物感谢、签到等插件的文案会自动跟着变，无需它们各自适配。

## 指令

在直播间直接发送（**不带方括号**，整条消息精确匹配）：

| 指令 | 作用 |
|------|------|
| `昵称` | 查看自己的专属昵称 |
| `昵称 xxx` | 把专属昵称设置为 `xxx` |
| `重置昵称` | 取消专属昵称，恢复真实用户名 |

指令名与全部文案均可在插件配置页自定义。

## 行为说明

- **作用范围与时效**：昵称只作用于当前账户的直播间。事件里的用户对象每次事件都新建，
  因此替换是**单事件作用域**的——不会污染其他直播间或其他账户。
- **消费指令**：默认会**阻止**昵称指令弹幕继续传给其他插件（`block_command_message`），
  避免关键词回复等把 `昵称 xxx` 当普通弹幕处理。可在配置中关闭。
- **匿名用户**（用户 ID 为 0）不参与昵称。
- **持久化**：昵称映射存于插件数据目录 `nicknames.json`，在插件配置页可直接删除某人的昵称。

## 实现要点

本插件是框架事件能力的示范：

- `apply_nickname` 以 **priority=1000** 监听 `LivestreamUserEvent`
  （弹幕/礼物/进入/关注/提问/跨房弹幕/跨房礼物的共同基类），
  在其余插件之前改写 `event.user.display_name`。
- `on_command` 以 **priority=900** 监听弹幕，并且是**同步方法**——
  只有同步 handler 调用 `event.cancel()` 才能阻断传播（异步 handler 由事件总线
  并发调度，执行时其他 handler 早已派发完毕）。发送回执是异步操作，
  因此在同步 handler 内用 `asyncio.get_running_loop().create_task(...)` 发起。

详见 [插件开发指南](../../docs/plugin/PLUGIN_DEV_GUIDE.md) 的「事件优先级与传播控制」章节。
